# 受控自动化

自动化有三个入口：内置 Agent 规划、单次 CLI、外部 Agent 直接调用 Device Tool Runtime。选择直接调用时可减少设备模型请求，但不会减少参数验证、安全评估和确认步骤。

1. 用只读环境盘点和工具目录确认能力。
2. 读取目标的真实状态（文件窗口、应用 UI 树、服务状态）。
3. 请求一个具体动作，核对审批中的完整参数和目标。
4. 执行后重读状态并检查结果；返回失败时保留证据，不盲目重放写入。

无交互 CLI 拒绝无法确认的动作。A2A/MCP 默认写入等待设备本地终端，`ask` 默认拒绝；如显式开启桥接自动批准，令牌持有者获得进程权限范围的无人值守能力，详见 [A2A/MCP](a2a-mcp.md)。

nl2sh 不内置通用任务调度器。主机脚本可安排只读任务，但调度、服务守护、权限与批准方式必须显式配置。不要把 `/shell` 或 companion 调试广播当成经过 Agent 安全链的自动化接口。
