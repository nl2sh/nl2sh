# 安全确认

执行边界始终是 `LLM → Security → Confirmation → Execution`。模型说明不构成批准；Root、工具参数和用户编辑都不能跳过分类。默认 balanced/risk-only 下：

| 风险 | 默认决定 |
| --- | --- |
| ReadOnly | 普通只读查询可自动运行，Root/strict 条件另需确认 |
| Mutating | 展示动作并确认 |
| Dangerous / Critical | 强确认 |
| 无法可靠解析、动态执行 | 保守评估，要求强确认 |

## TUI / CLI

先看完整命令或 diff、本地风险和规则依据。TUI 支持允许一次、任务内允许完全相同普通命令、运行期允许普通修改、拒绝、编辑、交互/捕获执行。任务许可不匹配前缀；运行期许可只保存在内存。`/permission allow` 开启运行期普通修改许可，`/permission ask` 关闭。Root、高风险和强确认不获得这些许可。非交互 CLI 无法取得必要批准时拒绝。

强确认的文字按当前提示输入；不要把自然语言“可以”当作所有后续动作的授权。编辑后整个分类/确认链重新运行。

## Web

修改单次点击批准；危险操作先点击进入复核，再第二次点击最终批准，不需要输入 `CONFIRM`。服务端核对待决编号和复核状态，旧窗口不能批准后续请求。拒绝与编辑后重评估仍可用。

## A2A / MCP

默认 `ask` 拒绝待确认操作；`invoke` 等待另一个设备交互终端的一次性审批，120 秒超时拒绝，危险类还需精确短语。网关不提供批准接口。

!!! warning "显式桥接自动批准"

    `bridge_auto_approve = true` 会让桥接 `ask` / `invoke` 自动批准所有等级，包括危险/严重动作。它默认关闭，仅桥接入口使用；安全分类、校验和身份绑定仍运行。只向完全信任的客户端提供网关令牌。

安全机制不能保证模型理解正确。批准前核对目标与副作用，无法确定时拒绝并要求先做只读诊断。详见 [安全模型](../reference/security-model.md)。
